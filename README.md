# UELT Web — спільний переклад .locres

Веб-застосунок для командної роботи над файлами `.locres` (Unreal Engine): акаунти, проєкти, доступ до окремих файлів, статуси рядків, прогрес і присутність у реальному часі.

## Вимоги
- Node.js **≥ 22.13** (використовується вбудований `node:sqlite`). Залежностей npm немає.

Оновити Node на Ubuntu: `curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt-get install -y nodejs`.

## Запуск
```
npm start            # http://localhost:3000
npm test             # 84 тести
```
Змінні середовища: `PORT`, `HOST`, `UELT_DB` (шлях до бази, за замовчуванням `data/uelt.db`), `UELT_SECURE_COOKIES=1` (лише якщо весь доступ іде через HTTPS; за проксі з X-Forwarded-Proto: https Secure вмикається сам). Якщо вхід «нічого не робить» — зазвичай це Secure-cookie при відкритті сайту по http.

## Перший вхід
Перший зареєстрований користувач автоматично стає **власником** порталу. Зробити адміном іншого: `npm run make-admin -- <нік>`. Аварійно призначити власника: `node src/cli.js make-owner <нік>` (попередній власник стає адміном).

## Ролі та доступ
Дві області: **портал** (власник, адмін, користувач) і **проєкт** (менеджер, перекладач, редактор, рецензент, спостерігач). Права перевіряє сервер за єдиною таблицею `src/roles.js`; інтерфейс лише ховає недоступні кнопки. Зведена матриця: `project.md`, §3.2.

| Роль | Область | Що може |
|---|---|---|
| **Власник** | портал | Усе. Єдиний: налаштування порталу, призначення/зняття адмінів, передача власності. Його не можна понизити, вимкнути чи видалити. |
| **Адмін** | портал | Створює проєкти й керує ними (учасники, файли, архів, видалення), бачить усі проєкти, керує звичайними користувачами. Не чіпає власника та інших адмінів. |
| **Менеджер** | проєкт | Керує *своїм* проєктом: учасники й ролі (крім менеджерів), доступ до файлів, завантаження, експорт, оновлення оригіналу, очищення, видалення файлів, журнал активності. |
| **Перекладач** | проєкт | Перекладає **призначені** файли (галочки доступу); переклад іде «На вичитку». |
| **Редактор** | проєкт | Править переклад у **усіх** файлах проєкту; не затверджує. |
| **Рецензент** | проєкт | Править і **затверджує** рядки в усіх файлах проєкту. |
| **Спостерігач** | проєкт | Лише перегляд файлів, рядків, статистики й присутності. |

- Імпортувати переклад (`.locres` / `.csv`) можуть менеджер, редактор, рецензент і перекладач (лише призначений файл); завантажувати й скачувати файли — менеджер, адмін, власник.
- Власник і адмін бачать усі проєкти без додавання в учасники; решта користувачів бачать лише проєкти, до яких їх додали. Сторонньому проєкт відповідає 404.
- Заархівований проєкт — тільки читання для всіх, включно з власником (розархівувати може власник/адмін).
- Не-рецензент, який змінив затверджений рядок, скидає його в «На вичитку».
- **Передача власності:** Адмінка → «Передати власність…» (потрібен пароль; сеанси обох завершуються, колишній власник стає адміном). Аварійно: `node src/cli.js make-owner <нік>`.
- **Оновлення з попередньої версії:** міграція ролей автоматична (найстаріший адмін → власник, інші адміни → адмін; учасник із правом затверджувати → рецензент, решта → перекладач). Зробіть резервну копію БД перед оновленням: `node deploy/backup.mjs data/uelt.db backups`.

## Статуси та статистика
Зміна перекладу → «На вичитку». Порожній переклад або рівний оригіналу → «Без статусу». «Перекладено» = На вичитку + Затверджено; «Затверджено слів» — слова рядків зі статусом Затверджено. Редагування затвердженого рядка не-затверджувачем скидає його в «На вичитку».

## Сповіщення на пошту
Про нову реєстрацію та видалення користувача (адміном або самим користувачем) сервер шле лист на `*****@gmail.com` (змінюється через `UELT_NOTIFY_TO`). Потрібен SMTP-акаунт: змінні `UELT_SMTP_HOST`, `UELT_SMTP_PORT` (465 або 587), `UELT_SMTP_USER`, `UELT_SMTP_PASS`, `UELT_SMTP_FROM`. Для Gmail створіть «Пароль застосунку». У Docker скопіюйте `deploy/.env.example` у `deploy/.env` і заповніть. Без налаштувань листи лише пишуться в лог. Збій пошти не заважає реєстрації.

## Профіль
У «Мій кабінет» (клік по ніку вгорі) користувач вказує емейл, Discord і Telegram (нік або телефон), змінює пароль або видаляє акаунт. Контакти бачить лише адміністратор (вкладка «Користувачі»).

## Імпорт готового перекладу
Один пункт «Імпортувати переклад (.locres / .csv)…» (меню дій файлу на сторінці проєкту й у редакторі; для адміна та людей із правом редагування файлу). Обробник вибирається за розширенням, незалежно від формату джерела файлу (`.csv` можна імпортувати у файл із `.locres`-джерела й навпаки — зіставлення йде за ключем).
- **.locres:** звіт → підтвердження. Збіг за ключем, нові переклади отримують статус «На вичитку»; можна перезаписати наявні та (для рецензентів) одразу затвердити.
- **.csv:** попередній перегляд із дією для кожного рядка (див. нижче).

## Файли проєкту: .locres і .csv
Адмін завантажує в проєкт `.locres` або `.csv` (drag-and-drop, тека). CSV-джерело має стовпці `key` (ID `Namespace::Key`) і `source` (оригінал), за потреби `translation` та `status` (`0/1/2` або `none/review/approved`; статус береться лише від адміна). Роздільник і кодування визначаються автоматично; реальні переноси рядків у полях перетворюються на службові маркери (`<lf>` тощо). Переклад, що збігається з оригіналом, вважається відсутнім. «Оновити оригінал» для CSV-файлу приймає CSV зі стовпцями `key,source`.

## Скачування файлу (адмін)
«Скачати…» (на сторінці проєкту й у редакторі) відкриває діалог: формат `.locres` або `.csv`.
- **.csv** — стовпці `key,source,translation,status`; параметри: які рядки (усі / без перекладу / на вичитку / затверджені / незатверджені / з перекладом), роздільник (`;` за замовчуванням, `,`, табуляція), BOM для Excel, «безпечний режим» (апостроф перед `= + - @`; при імпорті такого файлу передається `safe`). Службові маркери `<lf>`, `<tb>` виводяться як є, тому експорт імпортується назад без змін.
- **.locres** — для файлів із `.locres`-джерела зберігаються версія, хеші й шифрування CV2. Для файлів із CSV-джерела хеші рахуються (CRC32 від простору імен, ключа та оригіналу), версія 0 / 1 / 2 (за замовчуванням 2); версії з CityHash64 недоступні.
API: `GET /api/files/:id/export?format=locres|csv&scope=…&delimiter=semicolon|comma|tab&bom=0|1&safe=1&version=0|1|2`.

## CSV-імпорт перекладів

Оберіть .csv у пункті «Імпортувати переклад (.locres / .csv)…». Роздільник (кома, крапка з комою, табуляція, `|`) і кодування (UTF-8, UTF-16 з BOM, windows-1251) визначаються автоматично; роздільник можна змінити вручну в діалозі попереднього перегляду. Підтримуються лапковані поля та заголовки `key,translation` або `ключ,переклад`; необов'язковий стовпець `status` (`1`/`2` або `review`/`approved`) береться лише від того, хто має право затверджувати. Якщо файл скачано з «безпечним режимом для Excel», увімкніть відповідний прапорець у діалозі. Ключ має збігатися з ID рядка у UELT (`Namespace::Key`).

Спочатку показується попередній перегляд. Для кожного рядка можна пропустити імпорт, заповнити порожній переклад або замінити наявний. Невідомі ключі пропускаються; затверджені рядки може змінювати лише користувач із правом затвердження. Імпортований текст отримує статус «На вичитку». Зміни записуються в історію правок.

У «Мій кабінет» можна змінити власний нік (3–64 символи, без пробілів). Адміністратор може відкрити й відредагувати кабінет користувача у вкладці «Користувачі»; сервер перевіряє права на кожному запиті.

## Code Vein 2 (шифрований LUT)
При завантаженні файлів у зоні завантаження оберіть «CV2 Release» або «CV2 Demo» — файл розшифровується, а при експорті шифрується тим самим набором ключів. Оновлення оригіналу використовує набір, збережений для файлу. Якщо файл зашифрований, а набір не обрано, імпорт пройде, але тексти будуть нечитабельні — видаліть файл і завантажте з потрібним набором.

## Оновлення оригіналу
На сторінці проєкту кнопка «Оновити оригінал» (адмін): завантажуєте нову версію .locres, бачите звіт (нові / змінені / зниклі рядки) і підтверджуєте. Рядки зіставляються за ключем `Namespace::Key`; переклади зберігаються, у рядків зі зміненим оригіналом статус стає «На вичитку», зниклі рядки видаляються разом з перекладом. Відкриті редактори автоматично перезавантажують список.

## Розгортання
Потрібен сервер (VPS) з доменом, що вказує на нього.
- **Docker (найпростіше):** у `deploy/Caddyfile` впишіть свій домен, потім з кореня проєкту `docker compose -f deploy/docker-compose.yml up -d --build`. Caddy сам отримає HTTPS-сертифікат; дані лежать у томі `uelt-data`.
- **Без Docker:** `deploy/uelt.service` (systemd) + Caddy/nginx перед ним.
- Далі зареєструйтеся першим (станете адміном) і за потреби вимкніть вільну реєстрацію в адмінці.
- **Резервні копії:** `node deploy/backup.mjs data/uelt.db backups` (безпечно під час роботи сервера); поставте в cron раз на добу.

## Безпека
scrypt для паролів, сесії з хешем токена в БД, HttpOnly SameSite=Lax cookie, CSRF-заголовок `X-UELT`, обмеження спроб входу, CSP. Мінімальна довжина пароля — 6 символів.

## Обмеження
- Скачувати файли (.locres і .csv) може лише адміністратор.
- Хеші записуються як прочитані (CityHash64 не перераховується).
- Не можна додавати нові рядки (лише редагувати існуючі).
